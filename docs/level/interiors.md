# Интерьеры: клуб «Луна» и магазин «Луна 24ч» (T36)

Статус: готовы две отдельные сцены и универсальная интерактивная дверь.
В `scenes/world/block.tscn` интерьеры **не инстансятся** — там только зарезервированы
входы (дверные панели + рамки) и висят двери с `interior_door.gd`. Инстансы
подключает интегратор в `scenes/main.tscn` (файл Рэма).

## 1. Что сделано

| Файл | Что это |
|---|---|
| `scenes/interiors/club.tscn` | клуб «ЛУНА», 12×12 м, высота 5.6 м |
| `scenes/interiors/shop.tscn` | магазин «Луна 24ч», 8×6 м, высота 3.6 м |
| `scenes/interiors/interior_scene.gd` | корневой скрипт: режим «отдельная сцена / инстанс в игре», вращение свет-«качелей» |
| `scripts/world/interior_door.gd` | дверь: teleport внутрь/наружу, точка возврата, метаданные для `Interactor` |
| `scenes/world/block.tscn` | узлы `InteriorEntrances/ClubDoor`, `InteriorEntrances/ShopDoor` + рамки/неон |

Материалы — только существующие PBR-ресурсы: `concrete_pbr`, `metal_pbr`,
`brick_grey_pbr`, `brick_red_pbr`, `neon_magenta`, `neon_cyan`, `door_glass`,
`window_warm`, `prop_plastic`, `prop_wood_olive`, `prop_sign_white`,
`prop_bag_dark`. Новые текстуры/материалы не создавались.

## 4. Двери и точки перехода

Дверь — `StaticBody3D` со скриптом `scripts/world/interior_door.gd`. Совместима с
существующим `Interactor`: в `_ready` ставит meta `interactable=true`,
`display_name` и `interact_hint`; `Interactor` вызывает `interact(player)`.
После телепорта скрипт ждёт один кадр физики и делает `force_update_transform()`
игроку и `Camera3D`, чтобы SpringArm/камера не «проваливались».

| Дверь | Где | Координаты (мир) | Ведёт |
|---|---|---|---|
| `InteriorEntrances/ClubDoor` | фасад клуба, юг | (0, 1.32, −65.84) | в клуб, маркер группы `interior_club` |
| `InteriorEntrances/ShopDoor` | вход «Луны» | (−4, 1.22, −11.84) | в магазин, маркер группы `interior_shop` |
| `Club/ExitDoor` | клуб, южная стена | локально (0, 1.32, 5.82) | наружу: сохранённый возврат или (0, 0.15, −64.4) |
| `ShopInterior/ExitDoor` | магазин, южная стена | локально (0, 1.22, 2.82) | наружу: сохранённый возврат или (−4, 0.1, −10.6) |

Точки входа внутри сцен: `ClubEntry` (0, 0.05, 4.4) — группа `interior_club`;
`ShopEntry` (0, 0.05, 2.1) — группа `interior_shop`. Поворот маркера задаёт
направление игрока после входа (смотрит вглубь).

Возврат «наружу»:
1. meta `interior_return` на игроке (сразу после входа);
2. флаг `QuestState` `interior_return_club` / `interior_return_shop` —
   массив `[x, y, z, yaw]`; флаги уже попадают в `user://save.json`, так что позиция
   возврата переживает сохранение/загрузку;
3. `fallback_exit_position` двери (если игрок загрузился сразу внутри).

## 5. Как подключить (задача интегратора, scenes/main.tscn — Рэм)

1. Импортировать сцены и добавить в `Main` узел `Interiors` (Node3D).
2. Инстансы можно ставить где угодно вне видимого мира, например:
   - `Main/Interiors/Club` (instance `scenes/interiors/club.tscn`), position `(0, −200, 0)`;
   - `Main/Interiors/Shop` (instance `scenes/interiors/shop.tscn`), position `(0, −200, 60)`.
   Важно только, чтобы интерьеры не пересекались с игровым миром по координатам.
3. Ничего вручную связывать не нужно: уличные двери находят `ClubEntry`/`ShopEntry`
   по группам `interior_club` / `interior_shop`.
4. Корневой скрипт интерьеров при инстансе в игре сам выключает `PreviewCamera`
   (чтобы не отобрать камеру у игрока) и `WorldEnvironment` (чтобы локальный туман
   не перекрыл ночную улицу). Если нужен туман клуба при входе — включить
   `Interiors/Club/WorldEnvironment.environment` по сигналу двери
   `entered_interior` и выключить по `exited_interior`.
5. Для звука/атмосферы: те же сигналы `entered_interior(from)` / `exited_interior(to)`
   у дверей — удобные точки для `AudioManager`/ambience-зон.

отдельная сцена`.
