# Голосовые профили персонажей (t29)

Озвучка «Ночной смены» собрана из **четырёх офлайн-моделей piper** и **девяти
уникальных профилей** (модель + темп + питч + эффект). До t29 голосов было два
(irina/denis), и почти все мужские персонажи звучали одинаково; теперь у каждого
свой тембр, манера и, где нужно, эффект.

Движок: `tools/gen_voice_piper.py`. Профили заданы в словаре `PROFILES` по имени
спикера из `scripts/dialogue/data/voice_manifest.json`. Текущее состояние:
**26 диалогов, 207 узлов, 203 озвученных файла** (4 узла — немая пауза «...»/«…»).

## Как считается питч

Питч меняется **без изменения длительности** (не «бурундуки»):

1. линейный ресемплинг сигнала к длине `N / pitch` — питч умножается на `pitch`,
   длительность делится на `pitch`;
2. OLA-растяжение (`time_stretch`, окно Ханна 1024 отсчёта, перекрытие 75 %,
   анализный шаг = `hop × speed`) возвращает исходную длину.

Нормировка OLA — на **сумму окон** `Σ win`, а не на `Σ win²`: при `Σ win²` в
числителе стоит `samples·win`, и на краях окна Ханна (`win → 0`) получается
`samples / win` — деление на почти ноль выжигало одиночный сэмпл в клик (пик
вырастал до 149 % FS, а `limit_peak` потом ронял весь файл). После исправления
пик после питч-сдвига — ровно −1 dBFS.

## Как воспроизвести

```powershell
python tools\gen_voice_piper.py --fetch      # докачать dmitri/ruslan (HF, ~63 МБ каждый)
python tools\gen_voice_piper.py --dry-run    # план: сколько файлов на профиль
python tools\gen_voice_piper.py --force      # перегенерировать все WAV
$env:APPDATA="$PWD\.godot_profile"
tools\Godot_v4.7.2-stable_win64_console.exe --headless --path . --import
python tools\gen_voice_piper.py --verify     # длина/пик/RMS по каждому персонажу
```

`--fetch` качает модели с HuggingFace (`rhasspy/piper-voices`, `ru/ru_RU/<name>/medium/`)
тем же способом, что и `tools/fetch_piper.py`: python `urllib`, `.onnx` + `.onnx.json`.
Если модели уже лежат в `tools/piper/voices/`, `--fetch` печатает «все модели на месте».

`--dry-run` только печатает план и всегда возвращает код 0; обрыв трубы при
`| Select-Object` тоже больше не считается ошибкой (UTF-8 + BrokenPipe-гард).

`--verify` печатает по строке на персонажа: число файлов, минимальную длительность,
диапазон пика, минимальный RMS и профиль. Нарушения (длительность < 0.5 с,
пик вне −1…−6 dBFS, RMS < 1000 в шкале int16, пропавшие файлы) перечисляются
в конце; код возврата 1 — есть нарушения.

Текущий прогон: `проверено файлов: 203; нарушений: 0`, минимальный RMS по
персонажам 1515 (Голос в трубке, пик −4.0 — так задумано) … 3936 (Костя).

## Как поменять голос персонажа

1. Правится только `PROFILES` в `tools/gen_voice_piper.py` (это не сюжетный текст).
2. `python tools\gen_voice_piper.py --only <dialogue_id> --force` — перегенерировать
   затронутые диалоги (или `--force` для всех).
3. Импорт в Godot (команда выше).
4. `python tools\gen_voice_piper.py --verify` — убедиться, что пик/длина в норме.

Новый персонаж без профиля получает `DEFAULT_PROFILE` (denis, 1.00, ×1.00) — это
осознанный фолбэк, чтобы озвучка не пропадала; `--dry-run` сразу покажет такого
спикера с denis-профилем, и ему можно назначить свой.

## Ограничения

- Питч-сдвиг ±10 % — предел без «бурундуков» на OLA; сильнее двигать не стоит.
- Моделей четыре, поэтому часть различий держится на темпе и питче, а не на тембре:
  Нил и Костя — один denis (у Кости темп +4 % и питч +3 %), Прораб и Проверяющий —
  один ruslan (у Проверяющего питч +3 %, темп +8 %).
- «Плёнка» и «Запись» — один и тот же диктофонный профиль (это одна и та же плёнка
  в сюжете).
- Пик у «Голоса в трубке» ≈ −4 dBFS — так задумано (телефон тише), проверка
  `--verify` допускает −1…−6 dBFS.
- 4 узла не озвучены намеренно: `voice/voice_03`, `cut_box/cb_03`,
  `cut_weapon/cw_03`, `cut_weapon_alt/cwa_03` — в тексте «...»/«…», это немые
  паузы, субтитры остаются.
