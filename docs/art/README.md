# Арт-пак реализма: почему процедурно и что с CC0

Автор: Сакура (art-director). Короткий ответ: **CDN-хосты ассетов в этой сети недоступны**,
поэтому реализм сделан процедурно (numpy + Pillow), а путь CC0-ассетов оставлен открытым
на будущее — скрипты целы и включаются одной командой, когда сеть это позволит.

## 1. Что проверили (замеры капитана, 2026-10-26)

| Хост | Что тестировали | Результат |
| --- | --- | --- |
| `dl.polyhaven.org` | 3 МБ jpg текстуры | висел > 600 с, три ретрая по 180 с, затем `TimeoutError` |
| `api.polyhaven.com` | API `assets` / `files` | **работает** (869 текстур, 521 модель) — но без CDN это бесполезно |
| `ambientcg.com` | API `?full_json` | 200 за 0.5 с |
| `ambientcg.com` | архив `?file=Asphalt012_2K-JPG.zip` | `TimeoutError` за 26 с |
| `raw.githubusercontent.com`, `github.com` | — | **работают** (0.3 / 0.8 с) |
| `github.com` releases | Godot 82 МБ | скачалось нормально |
| HuggingFace | piper 22 МБ, голоса 63 МБ | скачалось нормально (используется для озвучки) |

Вывод: **любые CDN ассетов (Poly Haven, ambientCG) недоступны**, а файловые хостинги
GitHub/HF работают. Скачать 2k-JPG и glTF-модели оттуда нельзя.

## 2. Что сделано вместо этого

Процедурная генерация: `tools/gen_pbr_textures.py` (Python 3.10, numpy + Pillow).
7 наборов × 4 карты, 2048², полный тайлинг (шум генерируется фильтрацией в частотной
области — сетка периодическая; кладка/доски/черепица считаются по дробным координатам
с целыми периодами). В `docs/art/pbr_manifest.json` пишется ошибка шва по каждому набору.

| Набор | Что это | Материал | uv1_scale | Где применён |
| --- | --- | --- | --- | --- |
| `asphalt` | крупный заполнитель, трещины, редкие мокрые пятна | `asphalt_pbr.tres` | 20 | `Ground`, дорога |
| `brick` | кладка 8×24, расшивка, разброс тона по кирпичу | `brick_red_pbr.tres`, `brick_grey_pbr.tres` | 6 / 7 | `BuildingA`, новые постройки |
| `concrete` | моттлинг, каверны, потёки | `concrete_pbr.tres` | 5 | `BuildingB`, `Perimeter`, `Slope` |
| `plaster` | тонкий шум, затёртые разводы, трещинки | `plaster_pbr.tres` | 5 | задние стены, резерв |
| `metal` | шлифовка, швы 2×2, заклёпки, ржавые пятна | `metal_pbr.tres` | 3 | двери, трубы, рамы |
| `dock_planks` | доски 5 рядов, волокно, сучки, щели | `dock_planks_pbr.tres` | 6 | `PierDeck`, ящики, лавка |
| `roof` | черепица с нахлёстом | `roof_pbr.tres` | 4 | крыши, резерв |

Плюс 5 простых материалов для пропсов: `prop_wood_olive`, `prop_plastic`, `prop_sign_white`,
`prop_bag_dark`, `prop_rust`.

Нормали строятся из height через центральные разности с **флипом G** (OpenGL/Godot), AO —
из разницы height и размытой копии. Всё своё: лицензий и атрибуции нет вообще.

## 3. Ревизия двух материалов по живому кадру

1. **`assets/materials/asphalt.tres`** (он стоит в `block.tscn`, поэтому правка видна сразу):
   было roughness 0.72 × FastNoiseLite с uv1_scale 32 → контрастные пятна читались как «лужи
   масла» и золотые блики. Стало: база 0.82, noise-разброс 0.78…1.0 (мягко), частота 0.008,
   uv1_scale 12, metallic 0.15, specular 0.45. Мокрость — намёком, а не по всей плоскости.
2. **`assets/materials/door_glass.tres`** (витрина «Луны», `Shop/Entrance` 2.4×3 м):
   было emission `(0.3,0.85,1)` ×1.0 при metallic 0.6 / roughness 0.06 → bloom выжигал
   плоскость в белый cyan-прямоугольник. Стало: emission `(0.12,0.34,0.42)` ×0.95,
   roughness 0.16, metallic 0.15, albedo темнее. Плюс в `scenes/props/props.tscn` добавлен
   `ShopWindowFrame` — три вертикальных и два горизонтальных импоста (`scenes/props/window_frame.tscn`,
   материал `metal_pbr`), они перекрывают свечение и дают переплёт.
   Неоновая вывеска (`neon_magenta` ×2.2 / `neon_cyan` ×1.9) **не тронута** — по кадру она хороша.

## 4. Пропсы (вместо glTF-моделей)

10 типов из примитивов, 16 экземпляров + переплёт витрины, `scenes/props/props.tscn`.
У каждого пропса `StaticBody3D` + `CollisionShape3D` (проходы — 4 м в переулке — не блокируются,
пропсы стоят у стен). Типы: `crate_wood`, `crate_military`, `crate_plastic`, `barrel`, `bench`,
`pipes`, `ladder`, `wet_sign`, `trash_can`, `trashbag`.
Позиции — те же, что в `docs/art/realism_pack.md` (§3), координаты сняты с `block.tscn`.

| `asphalt.tres`: roughness | 0.82 | **0.75** |
| `asphalt.tres`: metallic / specular | 0.15 / 0.45 | **0.23 / 0.5** |

| `night_shift_env.tres`: tonemap_exposure | 1.1 | **1.2** |

Лампы в `block.tscn` правил только по числу `light_energy` (узлы, имена, коллизии, группы — без
изменений); если Эрен будет перезаписывать файл, эти 11 значений нужно перенести.

Метрика шва теперь честная (`tile_seam_ratio` = край / соседние пиксели внутри, 1.0 = шва нет)
и пишется в `docs/art/pbr_manifest.json`. Замеры капитана: asphalt 1.01/0.94, concrete 0.97/0.99,
plaster 1.03/1.02, metal 0.99/1.00 — шва нет; dock_planks 0.93/**1.26**, brick 1.72/1.69,
roof **2.04** по вертикали — это стык, совпадающий с расшивкой/гребнем, а не разрыв шума.
Красивее не сделать без сдвига рисунка: шов ложится ровно на линию кладки/доски/черепицы.

## 7. CC0 остаётся открытым на будущее

Скрипты `tools/fetch_art_assets.py` (Poly Haven API + валидация карт) и
`tools/build_art_pack.py` сохранены и рабочие — им нужен только доступ к CDN. Когда сеть
разрешит, порядок: `fetch_art_assets.py --dry-run` → `fetch_art_assets.py` →
`build_art_pack.py`; материалы лягут рядом с процедурными (`*_pbr.tres`) и подменяются
без изменения сцен.

Что имеет смысл проверить дешёвым HEAD-пробником (5 с), если появится доступ:

- GitHub: `raw.githubusercontent.com/KhronosGroup/glTF-Sample-Assets/...` — модели с
  разными лицензиями (есть CC0, но лицензия у каждого ассета своя — читать `LICENSE.md` репозитория);
- GitHub: `mrdoob/three.js` — `examples/textures/`, часть наборов CC0, но провенанс смешанный,
  без сверки лицензии каждого файла брать нельзя;
- HuggingFace: поиск датасетов по запросу `cc0 textures` / `polyhaven mirror` — если найдётся
  зеркало Poly Haven как датасет, это самый близкий путь к оригинальным CC0-наборам;
- `github.com` releases любых asset-паков (Kenney, Quaternius) — модели CC0 доступны как
  zip-релизы, а релизы GitHub у нас качаются.

Проверять так: `urllib.request` HEAD на 1 файл из кандидата, таймаут 5 с. Пока такого
подтверждённого источника нет — процедурный пак единственный, который реально работает.

## 9. Правило проверки материалов (после t35)

`t35` дал дорогой урок: в двух `.tres` была битая первая строка
(`[gd_resource type="StandardMaterial3D load_steps=…` — без закрывающей кавычки).
Godot не смог прелоадить материал → `Cannot infer the type of "MAT_METAL"` → падали
`world.gd`, `block.tscn`, пропсы и headless-прогоны у трёх агентов. Файлы текстовые,
поэтому проверять их обязательно **до** сдачи:

```powershell
& .\tools\Godot_v4.7.2-stable_win64_console.exe --headless --path . --check-only `
    --script res://assets/materials/metal_pbr.tres --log-file tools\t_art_check.log
# или хотя бы: --headless --path . --quit-after 5 --log-file tools\t_art_check.log
```

Правило: любой новый/правленый `.tres` + `grep -n 'gd_resource' assets/materials/*.tres`
на предмет незакрытой кавычки; после правки — `--import` (exit 0) и headless 300 кадров.

### Искра металла: закрыто в t45

`metal_pbr.tres`: roughness_texture отключена (constant 0.55), `normal_scale` 0.50,
`metallic` 0.80, `metallic_specular` 0.40. **Критерий закрыт кадрами t45**
`docs/shots_t45b/rails_a.png` / `rails_b.png`: это поручни лестницы в переулке
(`RailL`/`RailR`, y ≈ 3.08) — перил пирса отдельными мешами в сцене нет, поэтому
прошлый ракурс «вдоль пирса» смотрел в пустой настил. На поручне блик читается по грани,
чистых 255,255,255 нет (выбит только плафон лампы — это нормально).
История: A/B `docs/shots_art4/rail{1..4}_{before,after}.png` был недоказательным —
белые пиксели оказались фонарными выбросами. Запас, если искра вернётся на других
ракурсах: `normal_scale 0.30` или `normal_enabled = false`.
Телепорт игрока на произвольные ракурсы не держится (контроллер выталкивает из коллизий):
для съёмки использовать свободную `Camera3D` на изолированном инстансе, не `teleport_to`.

## 10. Город: палитры, окна, витрины (t42)

Город T32 (360×358 м, 66 корпусов) стоит на MultiMesh и одном общем материале окон —
поэтому дальние фасады читаются «плитами», а окна светятся полосами. Ниже — материалы,
которые закрывают это **без правок геометрии**: их подключает Эрен в `world.gd`
(единственное место, где задаются материалы города).

### 10.1. Палитры 4 кварталов

| Материал | Файл | База / тон (`albedo_color`) | uv1_scale (номинал) | Где применять |
| --- | --- | --- | --- | --- |
| Жилой | `city_facade_residential.tres` | `brick` (0.84, 0.70, 0.62) | 3.0 | кварталы у центра, 2–4 этажа |
| Коммерческий | `city_facade_commercial.tres` | `concrete` (0.62, 0.66, 0.74) | 2.5 | улицы кольца, 1-й этаж витрины |
| Складской | `city_facade_industrial.tres` | `concrete` (0.40, 0.42, 0.46) | 2.0 | север/восток, гараж, заправка |
| У воды | `city_facade_waterfront.tres` | `plaster` (0.36, 0.44, 0.56) | 2.5 | только южнее z ≈ −45 и у квэя |
| Пояс/цоколь (общий) | `city_trim_stone.tres` | `plaster` (0.70, 0.72, 0.76) | 2.0 | межэтажные тяги, обрамления витрин |

**Правило масштаба текстуры:** `uv1_scale` в файле — номинал для фасада 12×18 м.
Для дома другого размера `uv1_scale = размер_грани / 4.5` (жилой/коммерческий) или
`/ 6.0` (складской). В MultiMesh `uv1_scale` общий — значит либо 3–4 материала-варианта
по высоте дома, либо `INSTANCE_CUSTOM` в шейдере. Иначе кирпич на 36-метровом доме
растягивается в «плиту» — это и есть текущая проблема дальних фасадов.

| --- | --- | --- |
| `window_city_warm_a.tres` | (1, 0.62, 0.30) × 1.45 | основной тёплый, 55% окон |
| `window_city_warm_b.tres` | (1, 0.75, 0.46) × 1.20 | тёплый-жёлтый, 25% |
| `window_city_cool.tres` | (0.58, 0.76, 1.0) × 0.80 | холодный (офис/дежурный), 12% |
| `window_city_off.tres` | выкл. (metallic 0.35, roughness 0.08) | тёмное стекло, 8% |
| `window_city_warm_far.tres` | (1, 0.62, 0.30) × **2.40**, ambient off | дальний LOD ≥ 80 м |
| `window_city_cool_far.tres` | (0.58, 0.76, 1.0) × 1.35, ambient off | дальний LOD холодных |

**Чтобы окна читались прямоугольниками, а не полосами** (геометрия, зона Эрена):
1. Квад окна **1.1 × 1.5 м**, плоский `QuadMesh`, НЕ масштабировать по высоте этажа
   (полосы — это квад, растянутый на 12–36 м).
2. Шаг по горизонтали **2.4 м**, по вертикали **3.2 м** (этаж), подоконник 0.9 м,
   между окнами минимум 1.3 м стены.
3. Распределение: 55% warm_a / 25% warm_b / 12% cool / 8% off, детерминированный seed.
4. Дальние дома (≥ 80 м) — отдельная MultiMesh-группа с `window_city_*_far`: emission 2.4
   пробивает туман, ambient off не даёт «серой заливке», дом читается силуэтом с огнями.

### 10.3. Витрины и вывески: 6 материалов и правило улицы

| Материал | Тип | Где |
| --- | --- | --- |
| `storefront_glass_warm.tres` | тёмное стекло + тёплое свечение 0.22 | витрины главных улиц |
| `storefront_glass_cool.tres` | тёмное стекло + холодное свечение 0.25 | аптека/офис/24 ч |
| `storefront_shutter.tres` | жалюзи-металл (закрытая витрина) | 20–30% витрин |
| `storefront_roll_gate.tres` | ржавый роллет | автосервис, склады, служебные |
| `sign_neon_white.tres` | белый LED 1.35 | «24 Ч», такси, аптека |
| `sign_painted.tres` | крашеная плашка без свечения | 70% вывесок |
| `awning_canvas.tres` | тёмно-красный холст | маркизы над витринами |

Правило (чтобы город не стал ёлкой):
- **витрины — только 1-й этаж** и только на главных улицах: кольцо `x = ±120`, южная
  улица `z = −40`, коммерческий квартал и клуб; во дворах и на складах — роллеты;
- **неон — максимум 1 вывеска на 50 м**, белый LED — не чаще 1 на 40 м, остальные
  `sign_painted`;
- закрытых витрин **20–30%**, иначе улица светится ровным светом и теряет ритм;
- маркизы — через одну витрину: дают тень и человеческий масштаб.

### 10.4. Дальний план: сделано и рекомендация

Сделано (откат — одна строка): `night_shift_env.tres` — `fog_density` 0.02 → **0.016**,
`fog_aerial_perspective` 0.3 → **0.4**, `fog_sky_affect` 0.35 → **0.28**. Туман перестаёт
«съедать» кварталы, воздушная перспектива сохраняет глубину, небо не светлеет.
Основной инструмент — материалы дальнего LOD окон (10.2): дом читается силуэтом и огнями
на 200 м при `far = 200`.

Рекомендация Эрену по приоритету:
1. LOD-группы окон 80 м / 160 м — дешевле тумана, ближний кадр не трогают;
2. если дальние дома всё ещё «плиты»: `fog_aerial_perspective` до 0.5 и
   `ambient_light_energy` 1.1 → 1.15 (не больше — ambient почти не влияет на землю,
   зато поднимает стены);
3. `far` камеры 200 → 260 — только если после LOD нужен обзор: это зона Тандзиро.

Правила для владельцев:
1. **Не дублировать материалы.** Один `.tres` на семью: все стёкла машины — один

4. Если объект «пластиковый» — это не материал, а отсутствие отражений: добавьте в кадр
   один источник с shadow_enabled = false и проверьте `metallic`/`roughness` по таблице.
